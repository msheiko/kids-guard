# KidGuard (Telegram) — спецификация

Служба Windows 10 для родительского контроля доступа к ПК с управлением через Telegram-бота.

> Вариант без Home Assistant. Рабочее название — **KidGuard**. Идентификаторы в коде и логи — на английском. Комментарии, документация и **тексты бота — на русском**.

---

## 1. Цель

Родитель с телефона (Android или iOS, приложение Telegram) должен иметь возможность:

1. **Вручную включать и выключать доступ** ребёнка к ПК. Выключенный доступ означает, что ребёнок не может войти в Windows, а текущий сеанс завершается.
2. **Ограничивать длину сеанса** (опционально): после входа ребёнок работает N минут, получает предупреждения, затем сеанс завершается.
3. **Продлевать текущий сеанс** (+15 / +30 / +60 минут).
4. **Получать запросы времени** от ребёнка и отвечать на них кнопкой в чате.
5. Задавать **дневной лимит** и **расписание** разрешённых часов.
6. Видеть статус и получать уведомления (вход, «осталось 5 минут», завершение, ПК снова на связи).

Контроль обязан работать надёжно против обхода стандартным (не администратором) пользователем, включая отключение сети.

## 2. Окружение и допущения

- ПК ребёнка: **Windows 10 22H2 x64** (Home или Pro). Совместимость с Windows 11 желательна.
- У ребёнка **локальная стандартная учётная запись** (не администратор). У родителя на ПК отдельная учётная запись администратора с паролем.
- Бот создаётся родителем через @BotFather. Токен вводится при установке.
- ПК имеет исходящий доступ в интернет к `api.telegram.org` (HTTPS, порт 443). Входящие соединения и проброс портов **не нужны**.
- v1 контролирует **одну учётную запись ребёнка на одном ПК**. Управлять могут **несколько родителей** (список разрешённых пользователей).

## 3. Не входит в рамки (non-goals)

- Фильтрация сайтов и контроль приложений.
- Собственное мобильное приложение или веб-панель.
- Контроль учётных записей Microsoft (MSA) в v1.
- Защита от пользователя с правами администратора, загрузки с внешнего носителя, переустановки ОС. Против этого используются пароль BIOS/UEFI и отсутствие прав администратора у ребёнка.
- Внешний сервер для бота. Бот работает внутри службы на ПК (см. 4.2 — почему).

## 4. Архитектура

```
 Телефон родителя (Telegram)
        │
        ▼
 Telegram Bot API (api.telegram.org)
        ▲
        │ HTTPS, long polling (только исходящие соединения)
        │
 ПК ребёнка (Windows 10)
 ┌──────────────────────────────────────────────────────────────┐
 │ KidGuard.Service  (служба Windows, LocalSystem)              │
 │   • Telegram-бот (getUpdates, long polling)                  │
 │   • применение доступа (включение/отключение учётной записи) │
 │   • отслеживание сеансов, локальный таймер, расписание,      │
 │     дневной лимит, офлайн-политика                           │
 │   • запуск KidGuard.Tray в сеансе ребёнка                    │
 │            ▲  named pipe (ACL)                               │
 │            ▼                                                 │
 │ KidGuard.Tray  (процесс в сеансе ребёнка, без прав и секретов)│
 │   • показ предупреждений и оставшегося времени               │
 │   • кнопка «Попросить ещё времени»                           │
 └──────────────────────────────────────────────────────────────┘
```

### 4.1 Компоненты

**KidGuard.Service**
- Служба Windows, учётная запись `LocalSystem`, тип запуска «Автоматически».
- Единственный компонент с секретами (токен бота) и правами на изменение учётных записей.
- Является **источником истины**: хранит состояние, расписание, лимиты, таймер. Бот — только интерфейс к ним.

**KidGuard.Tray**
- Небольшое приложение (WinForms) в области уведомлений, запускаемое службой в сеансе ребёнка через `WTSQueryUserToken` + `CreateProcessAsUser` при входе ребёнка.
- Не хранит секретов и не принимает решений. Если ребёнок закроет его, служба перезапускает Tray (не чаще раза в 30 секунд) и в любом случае выполняет завершение сеанса сама.
- Показывает: оставшееся время во всплывающей подсказке значка, всплывающие предупреждения, сообщения от родителя.

**IPC Service ↔ Tray**
- Named pipe `\\.\pipe\KidGuard`. ACL: SYSTEM — полный доступ, учётная запись ребёнка — только подключение клиентом.
- Сообщения JSON. От службы к Tray: `status`, `warning`, `message`. От Tray к службе: `time_request`, `hello`.
- Через pipe нельзя изменить доступ, лимиты или таймер. Служба принимает от Tray только `time_request`.

### 4.2 Почему бот внутри службы, а не на сервере

- Не нужен свой сервер, VPN и открытые порты: служба сама опрашивает Telegram.
- Ребёнок не может «отрезать» бота от ПК, не отрезав интернет целиком, а отсутствие интернета закрывается локальным таймером и офлайн-политикой (раздел 7).
- Минус: когда ПК выключен или без сети, бот не отвечает. Telegram хранит неполученные обновления до 24 часов, поэтому команды, отправленные в это время, будут получены при включении ПК (правила их обработки — в 8.6).
- Код бота нужно изолировать за интерфейсом (`IControlChannel`), чтобы в будущем можно было вынести его на домашний сервер или добавить канал MQTT/Home Assistant без изменения логики.

## 5. Функциональные требования

### 5.1 Доступ (вкл/выкл)

- `access = ON`: учётная запись ребёнка включена, вход разрешён (с учётом расписания и дневного лимита).
- `access = OFF`:
  1. Учётная запись ребёнка **отключается** (эквивалент `net user <name> /active:no`; `NetUserSetInfo` с флагом `UF_ACCOUNTDISABLE`).
  2. Все сеансы ребёнка **завершаются** (`WTSLogoffSession`), включая отключённые сеансы при быстром переключении пользователей.
  3. Перед завершением активного сеанса Tray показывает предупреждение, даётся льготный период `access_off_grace_seconds` (по умолчанию 60, 0 — без задержки).
- Отключённая учётная запись остаётся отключённой при перезагрузке, сбое службы и без сети.
- Служба **никогда** не применяет действия к учётным записям администраторов и к учётной записи, под которой выполнена установка.

### 5.2 Итоговое правило «можно ли сейчас пользоваться ПК»

Учётная запись ребёнка включена, только если выполнены **все** условия:

1. `access = ON` (ручной выключатель);
2. сейчас разрешённое время по расписанию (если расписание включено) **или** действует ручное исключение «разрешить сейчас вне расписания» (см. 5.6);
3. дневной лимит не исчерпан (если включён) с учётом добавленного сегодня времени;
4. не идёт перерыв `cooldown` (см. 5.4).

Служба пересчитывает это правило раз в 30 секунд и при каждом событии. Причина блокировки (`manual`, `schedule`, `daily_limit`, `session_limit`, `cooldown`, `offline`) хранится и показывается в статусе.

### 5.3 Лимит сеанса

- `session_limit_minutes`: 0 — без лимита; иначе 1…480.
- Сеанс начинается при входе ребёнка (`SERVICE_CONTROL_SESSIONCHANGE` / `WTS_SESSION_LOGON`), заканчивается выходом.
- Таймер считается **службой локально** по монотонным часам (`Environment.TickCount64` / `Stopwatch`), не по системному времени.
- Предупреждения через Tray за 5 и за 1 минуту (настраивается).
- По истечении — завершение сеанса (без дополнительного льготного периода).
- Если до конца расписания или дневного лимита осталось меньше, чем до конца лимита сеанса, предупреждения и завершение привязываются к **ближайшей** границе.
- Изменение лимита во время сеанса применяется сразу; если новый остаток ≤ 0 — даётся 1 минута и следует завершение.

### 5.4 Защита от «перезайти и обнулить таймер»

После завершения сеанса **по лимиту сеанса** поведение задаётся `after_limit_mode`:

- `lock` (по умолчанию): `access` автоматически переключается в `OFF`, родителю приходит уведомление; вход возможен только после ручного включения.
- `cooldown`: вход запрещён `cooldown_minutes` (по умолчанию 60), затем снова разрешён.
- `none`: новый вход начинает новый сеанс.

Выход до истечения лимита и повторный вход в течение `session_merge_minutes` (по умолчанию 10) **продолжают** прежний сеанс. Состояние сеанса сохраняется на диск и переживает перезагрузку.

### 5.5 Дневной лимит

- `daily_limit_minutes` по дням недели (0 — без лимита). Пример: будни 120, выходные 240.
- Учитывается суммарное время всех сеансов ребёнка за сутки, сброс в 00:00 **в часовом поясе службы** (см. 5.12), а не по часовому поясу Windows.
- Продление (`+N`) в течение дня увеличивает и остаток сеанса, и остаток дневного лимита на N минут (только на сегодня).

### 5.6 Расписание

- Недельное расписание разрешённых интервалов, до 3 интервалов в день. Пример: Пн–Пт `16:00-20:00`, Сб–Вс `10:00-13:00, 15:00-21:00`.
- Расписание можно выключить целиком (тогда ограничивает только выключатель и лимиты).
- Ручное исключение: команда «Разрешить сейчас на N минут» открывает доступ вне расписания на указанное время (не меняя расписание).
- Время интервалов задаётся и проверяется **в часовом поясе службы** и по доверенному времени (см. 5.12). Смена часового пояса или часов Windows расписание не сдвигает.

### 5.7 Продление сеанса

- `+15 / +30 / +60` (или произвольное число 1…240 командой) добавляет время к текущему сеансу и к дневному лимиту на сегодня.
- Если сеанса нет: добавленное время сохраняется как «бонус» и применяется к следующему сеансу сегодня (сгорает в полночь).
- Продление **не включает** выключенный доступ: для этого есть отдельная кнопка.

### 5.8 Завершить сеанс сейчас

- Завершить текущий сеанс ребёнка (с льготным периодом), **не меняя** `access`.

### 5.9 Запрос времени

- Кнопка в Tray «Попросить ещё времени» (с необязательным коротким комментарием) → всем родителям приходит сообщение с кнопками: «+15», «+30», «+60», «Отказать».
- Первый ответивший родитель обрабатывает запрос; у остальных сообщение редактируется: «Обработано: +30 мин (Мама)».
- Ребёнок видит в Tray результат: «Время добавлено: +30 мин» или «Отказано».
- Не чаще одного запроса в 5 минут; запрос без ответа сгорает через 30 минут.

### 5.10 Сообщение ребёнку

- Родитель может отправить текст (до 200 символов), который покажется ребёнку уведомлением через Tray.

### 5.11 Сон, гибернация, блокировка экрана

- `count_sleep` (по умолчанию `false`): время сна или гибернации не засчитывается ни в сеанс, ни в дневной лимит (`PBT_APMSUSPEND` / `PBT_APMRESUMEAUTOMATIC`).
- Время при заблокированном экране (Win+L) **засчитывается**.
- Для учёта сна использовать часы, не идущие во сне (`QueryUnbiasedInterruptTime`), для контроля скачков времени (5.12) — часы, идущие во сне (`GetTickCount64`).

### 5.12 Время и часовой пояс

**Часовой пояс службы**

- Всё, что зависит от времени суток (расписание, граница суток для дневного лимита и учёта, сгорание «бонуса» в полночь, `/allow`, отчёты), считается в часовом поясе службы `time_zone` из конфига.
- По умолчанию `time_zone` — часовой пояс Windows **на момент установки** (Windows ID, например `Belarus Standard Time`). Можно задать явно параметром `--time-zone`.
- Дальнейшие изменения часового пояса Windows службой **игнорируются**. Изменить `time_zone` можно только через CLI с правами администратора (`set-time-zone`).
- Внутри служба хранит время в UTC и переводит в `time_zone` через `TimeZoneInfo.FindSystemTimeZoneById`, корректно обрабатывая переход на летнее время, если он есть в поясе.
- Установщик **отзывает у группы «Пользователи»** (`S-1-5-32-545`) право `SeTimeZonePrivilege` (LSA: `LsaRemoveAccountRights`), чтобы ребёнок не мог менять часовой пояс Windows. У администраторов право остаётся. `uninstall` возвращает право.
- Служба отслеживает изменение часового пояса Windows (`WM_TIMECHANGE` / изменения в `HKLM\SYSTEM\CurrentControlSet\Control\TimeZoneInformation`) и уведомляет родителей: после отзыва права это может сделать только администратор, так что это сигнал о подозрительной активности.

**Системное время**

- Стандартный пользователь не может менять системное время (`SeSystemtimePrivilege` по умолчанию только у администраторов). Установщик проверяет, что это право не выдано группе «Пользователи», и при необходимости отзывает его.
- Таймер сеанса и льготные периоды считаются по монотонным часам и от системного времени **не зависят**.
- **Скачки во время работы**: служба сравнивает приращение UTC с приращением `GetTickCount64`. Расхождение больше 2 минут считается скачком времени: запись в лог и уведомление родителям.
- **Откат при загрузке**: служба раз в минуту и при остановке сохраняет `last_trusted_utc`. Если после старта системное время меньше сохранённого (часы откатили, например, в BIOS), служба считает текущим временем `last_trusted_utc` + время с момента загрузки, пока не получит доверенное время, и уведомляет родителей.
- **Доверенное время при наличии сети**: служба сверяет системное время с заголовком HTTP `Date` ответов `api.telegram.org`. Если расхождение больше 2 минут, для расписания и границ суток используется скорректированное время (системное + поправка), родителям приходит уведомление.
- Откат времени назад **никогда не обнуляет** учёт за день: граница суток сдвигается только вперёд по доверенному времени.
- Остаточный риск: перевод часов вперёд в BIOS при выключенном ПК и без сети обнаруживается только при появлении сети. Закрывается паролем на BIOS/UEFI.

## 6. Уведомления родителям

Каждое уведомление включается и выключается отдельно (команда `/notify`, настройки общие для всех родителей):

| Событие | По умолчанию |
|---|---|
| Ребёнок вошёл в систему | вкл |
| Осталось 5 минут | выкл |
| Сеанс завершён (причина и длительность) | вкл |
| Запрос времени | всегда вкл (не отключается) |
| ПК снова на связи после офлайна (сколько не было связи, был ли в это время активный сеанс и сколько он длился) | вкл |
| Служба запущена после перезагрузки ПК | выкл |
| Подозрительное: скачок или откат системного времени, расхождение с доверенным временем, изменение часового пояса Windows, попытка неразрешённого пользователя писать боту | всегда вкл (не отключается) |

## 7. Работа без связи

- Вся логика (таймер, расписание, дневной лимит, выключатель) работает **локально**. Без интернета ничего не продлевается и не сбрасывается — просто нельзя управлять удалённо.
- Состояние «связь есть / нет» определяется по успешности запросов к Telegram. Время начала и конца каждого офлайна пишется в историю и показывается в `/today`.
- Известный сценарий обхода: ребёнок отключает Wi-Fi, чтобы до ПК не дошла команда «выключить доступ». Лимиты при этом всё равно срабатывают, но команда применится только после восстановления связи. Для строгого режима предназначена политика `lock_after` (ниже). В `docs/INSTALL.md` описать этот сценарий и рекомендовать `lock_after`, если он актуален.
- `offline_policy`:
  - `keep_last` (по умолчанию): действовать по текущему состоянию;
  - `lock_after`: если связи с Telegram нет дольше `offline_lock_minutes` (по умолчанию 15) **во время активного сеанса**, завершить сеанс и запретить вход до восстановления связи. Причина блокировки — `offline`.
- Переподключение с экспоненциальной задержкой (1 → 60 секунд).
- При восстановлении связи — уведомление родителям (если включено) с длительностью офлайна.
- Поддержка HTTP/SOCKS5-прокси для доступа к Telegram (параметр конфигурации), на случай если Telegram недоступен напрямую.

## 8. Telegram-бот

### 8.1 Авторизация

- Разрешённые пользователи хранятся в конфиге как **числовые Telegram user ID** (не username: его можно сменить).
- Сообщения и нажатия кнопок от всех остальных **игнорируются** (бот не отвечает ничего, чтобы не раскрывать своё назначение). Не чаще раза в час родителям приходит уведомление о попытке доступа с ID и именем.
- Бот работает **только в личных чатах**; сообщения из групп игнорируются, из групп бот выходит.
- **Привязка родителя**: при установке CLI выводит одноразовый код (6 цифр, действует 10 минут). Родитель отправляет боту `/start <код>` — его ID добавляется в список. Новые родители добавляются тем же способом командой CLI `pair` (на ПК, с правами администратора) или командой `/invite` от уже привязанного родителя, которая выдаёт новый одноразовый код.
- Удаление родителя: `/parents` → кнопка «Удалить» (нельзя удалить последнего).

### 8.2 Главное сообщение-панель

Команда `/start` (или `/status`) отправляет **панель**: одно сообщение, которое бот затем **редактирует** при нажатиях и обновляет раз в минуту, пока идёт сеанс (не чаще, чтобы не упереться в лимиты Telegram).

Текст панели (пример):

```
🖥 ПК: kid-pc  •  на связи
🔓 Доступ: ВКЛЮЧЁН
👤 Сеанс: идёт 42 мин, осталось 18 мин
📅 Сегодня: 1 ч 10 мин из 2 ч
🕒 Расписание: 16:00–20:00 (сейчас разрешено)
⏱ Лимит сеанса: 60 мин • после лимита: блокировать
```

Inline-кнопки панели:

```
[ 🔒 Выключить доступ ]          (или [ 🔓 Включить доступ ])
[ +15 ] [ +30 ] [ +60 ]
[ ⏹ Завершить сеанс ] [ 💬 Сообщение ]
[ ⏱ Лимит сеанса ] [ 📅 Расписание ]
[ ⚙ Настройки ] [ 🔄 Обновить ]
```

- «Выключить доступ» требует подтверждения, если идёт сеанс: «Ребёнок сейчас за ПК. Выключить через 1 минуту? [Да] [Сразу] [Отмена]».
- «Лимит сеанса» открывает подменю: `[Без лимита] [30] [45] [60] [90] [120] [Своё…]` и выбор режима после лимита `[Блокировать] [Перерыв] [Ничего]`.
- «Расписание» показывает текущее расписание и кнопки `[Вкл/Выкл расписание] [Изменить] [Разрешить сейчас на…]`.
- После действия бот показывает краткое подтверждение (`answerCallbackQuery`) и обновляет панель.

### 8.3 Команды

| Команда | Действие |
|---|---|
| `/start [код]` | Привязка по коду или показ панели |
| `/status` | Панель |
| `/on`, `/off` | Включить / выключить доступ |
| `/add <мин>` | Продлить сеанс (1…240) |
| `/end` | Завершить сеанс, не меняя доступ |
| `/limit <мин>\|off` | Лимит сеанса |
| `/daily` | Показать дневные лимиты; `/daily будни 120`, `/daily выходные 240`, `/daily пн 90`, `/daily off` |
| `/schedule` | Показать расписание; `/schedule будни 16:00-20:00`, `/schedule сб 10:00-13:00,15:00-21:00`, `/schedule off`, `/schedule on` |
| `/allow <мин>` | Разрешить сейчас вне расписания на N минут |
| `/msg <текст>` | Сообщение ребёнку |
| `/today` | Отчёт за сегодня: сеансы (начало–конец, причина завершения), итог |
| `/week` | Итоги за 7 дней по дням |
| `/notify` | Настройка уведомлений (кнопки вкл/выкл) |
| `/parents`, `/invite` | Управление родителями |
| `/help` | Справка |

Команды регистрируются через `setMyCommands`, чтобы появлялись в меню Telegram. Ошибки ввода — понятное сообщение с примером правильного формата.

### 8.4 Аудит

- Каждое действие родителя пишется в лог: кто (ID, имя), что, когда, результат.
- В отчётах `/today` и в уведомлениях указывается, кто из родителей выполнил действие («Доступ выключил: Папа»).

### 8.5 Технические требования к боту

- Библиотека **Telegram.Bot** (.NET), получение обновлений через `getUpdates` (long polling, timeout 50 с). Webhook не используется.
- Перед запуском опроса вызвать `deleteWebhook` (на случай, если токен раньше использовался с webhook).
- Учитывать лимиты Telegram (≈30 сообщений/с всего, 1 сообщение/с в чат, редактирование панели — не чаще раза в минуту на чат вне нажатий). При `429 Too Many Requests` — ждать `retry_after`.
- `offset` последнего обработанного обновления сохраняется на диск, чтобы после перезапуска не обрабатывать команды повторно.

### 8.6 Команды, полученные с задержкой

Если ПК был выключен или без сети, при подключении могут прийти накопленные обновления (до 24 часов). Правила:

- **Состояние** (`/on`, `/off`, лимиты, расписание): применяется только **последняя** команда каждого типа, независимо от давности. Это позволяет выключить доступ, пока ПК выключен.
- **Разовые действия** (`+N`, `/end`, `/allow`, `/msg`, ответы на запросы времени): игнорируются, если старше 10 минут. Отправителю приходит сообщение «Команда устарела и не выполнена: …».
- После обработки накопленных команд родителям отправляется сводка: что применено, что пропущено.

## 9. Конфигурация и состояние

Файл `C:\ProgramData\KidGuard\config.json` (редактируется установщиком и ботом; ребёнку недоступен):

```json
{
  "child_user": "kid",
  "device_name": "kid-pc",
  "time_zone": "Belarus Standard Time",
  "telegram": {
    "bot_token": "***",
    "allowed_user_ids": [123456789, 987654321],
    "proxy": null
  },
  "warnings_minutes": [5, 1],
  "access_off_grace_seconds": 60,
  "session_merge_minutes": 10,
  "cooldown_minutes": 60,
  "count_sleep": false,
  "offline_policy": "keep_last",
  "offline_lock_minutes": 15,
  "time_request_min_interval_minutes": 5,
  "stale_command_minutes": 10
}
```

Изменяемые родителем через бота настройки хранятся в `C:\ProgramData\KidGuard\state.json`:
- `access`, `session_limit_minutes`, `after_limit_mode`;
- `daily_limit_minutes` по дням недели, `schedule` и флаг его включения;
- текущий сеанс, бонус на сегодня, учёт за сегодня, ручное исключение `/allow`;
- настройки уведомлений, `telegram_offset`, открытые запросы времени, ID сообщений-панелей по чатам;
- `last_trusted_utc`, текущая поправка к системному времени, дата текущих учётных суток (в `time_zone`).

`time_zone` в `config.json` по умолчанию заполняется установщиком текущим поясом Windows (пример выше условный).

Запись — атомарная (временный файл + замена). История сеансов — `history.jsonl` (хранить 90 дней) для отчётов `/today` и `/week`.

Логи: `C:\ProgramData\KidGuard\logs\` (ротация, 14 дней) и Windows Event Log (источник `KidGuard`) для ошибок. Токен бота **никогда** не пишется в логи.

## 10. Безопасность и защита от обхода

1. **ACL на `C:\ProgramData\KidGuard\`**: наследование отключено, полный доступ только `SYSTEM` и `Administrators` (по SID: `S-1-5-18`, `S-1-5-32-544`). Ребёнок не может прочитать токен бота или изменить состояние.
2. **Токен бота** — главный секрет: кто его знает, может перехватывать обновления. Хранить в конфиге, зашифрованным через DPAPI в контексте машины (`DataProtectionScope.LocalMachine`) в дополнение к ACL. Если токен утёк — родитель перевыпускает его в @BotFather и обновляет командой CLI `set-token`.
3. **Каталог установки** (`C:\Program Files\KidGuard\`): ребёнок — только чтение и выполнение.
4. **Служба**: восстановление при сбое — перезапуск через 5 секунд (все сбои). Стандартный пользователь не может остановить службу; проверить дескриптор безопасности службы.
5. **Безопасный режим** (опционально, флаг установщика): регистрация в `HKLM\SYSTEM\CurrentControlSet\Control\SafeBoot\Minimal` и `\Network`.
6. **Отключённая учётная запись** — блокировка, переживающая перезагрузку и отсутствие сети.
7. Служба не удаляет, не переименовывает и не меняет пароль учётной записи ребёнка.
8. Защита от самоблокировки родителя: в `child_user` нельзя указать учётную запись из группы администраторов; проверка при установке и при каждом старте.
9. Авторизация в боте только по user ID из списка (раздел 8.1). У ребёнка может быть свой Telegram — он не должен иметь возможности ничего сделать, даже найдя бота.
10. **Время**: у группы «Пользователи» отозваны права `SeTimeZonePrivilege` и `SeSystemtimePrivilege`; расчёты ведутся в часовом поясе службы и по доверенному времени (раздел 5.12).

## 11. Установка и CLI

`KidGuard.Service.exe` с CLI, требует прав администратора:

- `install --user <имя> --token <токен бота> [--device-name ..] [--time-zone <Windows ID>] [--proxy ..] [--safe-mode]`
  — копирует файлы в `Program Files`, создаёт `ProgramData` с ACL, пишет конфиг (`time_zone` по умолчанию — текущий пояс Windows), отзывает у «Пользователей» права на смену часового пояса и времени, проверяет токен (`getMe`), регистрирует и запускает службу, **выводит одноразовый код привязки** и имя бота.
- `set-time-zone <Windows ID>` — сменить часовой пояс службы.
- `pair` — новый одноразовый код для привязки ещё одного родителя.
- `set-token <токен>` — заменить токен бота.
- `uninstall` — остановить и удалить службу, **включить учётную запись ребёнка**, вернуть «Пользователям» право смены часового пояса, удалить данные (подтверждение или `--keep-data`).
- `status` — состояние службы, связи с Telegram, доступа, сеанса, лимитов.
- `unlock` — аварийно включить учётную запись ребёнка и `access = ON` локально (на случай, если Telegram недоступен, а родитель рядом с ПК).

## 12. Технологии

- **.NET 8**, C#, Worker Service с `UseWindowsService()`.
- Telegram: **Telegram.Bot**.
- Tray: WinForms (`NotifyIcon`), .NET 8.
- Win32 через P/Invoke или `CsWin32`: `WTSEnumerateSessions`, `WTSQuerySessionInformation`, `WTSLogoffSession`, `WTSQueryUserToken`, `CreateProcessAsUser`, `NetUserGetInfo`/`NetUserSetInfo`.
- Публикация: `win-x64`, self-contained, single-file.
- Логирование: `Microsoft.Extensions.Logging` + Serilog (файл + EventLog) или аналог.

## 14. Сценарии приёмки

Модульные тесты в `*.Tests` (фиктивные часы, контроллеры и канал управления); пункты **[ручная]** — проверка на реальном ПК по чек-листу в `docs/INSTALL.md`.

1. `/off` при активном сеансе → подтверждение, предупреждение ребёнку, через 60 с выход, учётная запись отключена. **[ручная]**
2. `/on` → вход возможен (если позволяют расписание и дневной лимит).
3. Лимит сеанса 30 мин → предупреждения на 25-й и 29-й минуте, выход на 30-й.
4. Лимит изменён с 60 на 20 мин на 25-й минуте → выход через 1 мин.
5. `+15` на 28-й минуте при лимите 30 → выход на 45-й.
6. `after_limit_mode = lock` → после выхода по лимиту `access = OFF`, уведомление родителям.
7. `after_limit_mode = cooldown` → вход запрещён 60 мин, затем разрешён.
8. Выход на 10-й минуте, вход через 3 мин → сеанс продолжается с 10-й минуты.
9. Расписание 16:00–20:00, вход в 19:50 при лимите сеанса 60 → предупреждения в 19:55 и 19:59, выход в 20:00.
10. Дневной лимит 120, использовано 110, лимит сеанса 60 → выход через 10 минут.
11. `/allow 30` в 21:00 при расписании до 20:00 → вход возможен до 21:30.
12. Сеть отключена на 5-й минуте при лимите 30 → выход на 30-й без сети. **[ручная]**
13. `offline_policy = lock_after`, сеть пропала → через 15 мин выход и блокировка; при восстановлении — уведомление и восстановление доступа.
14. ПК выключен, родитель отправил `/off`, затем `+30` → при включении ПК доступ выключен, `+30` отклонён как устаревший, родителю пришла сводка.
15. Запрос времени из Tray → сообщение обоим родителям; один нажал «+30» → у второго сообщение отредактировано; у ребёнка «+30 мин».
16. Повторный запрос времени через минуту → отклонён.
17. Сообщение боту от неразрешённого пользователя → бот молчит, родителям уведомление (не чаще раза в час).
18. Неверный или устаревший код привязки → отказ.
19. Ребёнок убил процесс Tray → служба перезапускает его; выход по лимиту происходит. **[ручная]**
20. Ребёнок пытается остановить службу или прочитать конфиг → отказ в доступе. **[ручная]**
21. Перезагрузка посреди сеанса → сеанс продолжается в пределах `session_merge_minutes`, повторные команды из Telegram не выполняются (сохранённый `offset`).
22. Сон 2 часа при `count_sleep = false` → не засчитано.
23. Установка с `--user` = администратор → ошибка, ничего не изменено.
24. `uninstall` → служба удалена, учётная запись ребёнка включена.
25. `unlock` на ПК без интернета → вход возможен.
26. Часовой пояс Windows изменён (администратором) с +3 на −2 в 21:00 при расписании до 20:00 → вход по-прежнему запрещён; дневной учёт не сброшен; родителям уведомление.
27. Ребёнок пытается сменить часовой пояс в «Параметрах» → отказ Windows (нет права). **[ручная]**
28. Системное время переведено на 3 часа вперёд во время работы → скачок обнаружен, уведомление; при наличии сети расписание и граница суток считаются по доверенному времени.
29. Часы откатили в BIOS на день назад, ПК загружен без сети → служба использует `last_trusted_utc` + время с загрузки; дневной учёт не сброшен; уведомление при появлении сети.
30. Системное время расходится с `Date` от Telegram на 10 минут → используется поправка, уведомление.
31. Офлайн 40 минут с активным сеансом → после восстановления связи уведомление с длительностью офлайна и сеанса; офлайн виден в `/today`.

## 15. Этапы реализации

1. **Core**: модель состояния, правило доступа (5.2), таймер, расписание, дневной лимит, политики, служба доверенного времени и часового пояса (5.12), хранение; тесты сценариев 3–11, 13, 21–22, 26, 28–30.

4. **Telegram**: авторизация и привязка, панель с кнопками, команды, уведомления, устаревшие команды; тесты 14–18.
5. **CLI**: install / pair / set-token / uninstall / status / unlock, ACL, DPAPI, восстановление службы.
6. **Tray + IPC**: предупреждения, запрос времени, сообщения, перезапуск.
7. **Документация и ручная приёмка** по чек-листу.
